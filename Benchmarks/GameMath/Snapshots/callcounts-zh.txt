# GameMath calls per logic frame in Zero Hour.
#
# Measured with counters placed at the 52 call sites that reach GameMath: 51 in
# Core/Libraries/Source/WWVegas/WWMath/wwmath.h and 1 in
# GeneralsMD/Code/GameEngine/Source/Common/System/Trig.cpp, where gm_sqrtf is
# called directly. Counters are keyed on the gm_ function reached, not on the
# WWMath wrapper: WWMath::Fabsf and WWMath::Fabsf_Legacy both feed gm_fabsf.
#
# Run on macOS ARM64, GeneralsOnlineZH, GENERALS_ONLINE_HIGH_FPS_SERVER = 1, so
# 60 Hz logic. Counters dumped every 100 logic frames and reset. Multiplayer,
# eight slots, map Ring Ring 8.
#
# Two long battles, recorded in separate runs, are carried side by side so the
# spread between them is visible rather than averaged away:
#
#   battle44   44 min 20 s in total. Plateau: minutes 8 to 28, blocks 289-1008,
#              72 000 frames, 20 minutes. Around 30 000 calls per frame.
#              Source: callcounts-mac-arm64.txt, session 3.
#
#   battle69   69 min 30 s in total. Plateau: minutes 20 to 42, blocks 721-1512,
#              79 200 frames, 22 minutes. Around 29 000 calls per frame.
#              Source: callcounts-v2-mac-arm64.txt, session 3.
#
# In both cases the plateau is the stretch where the call volume has risen and
# holds, and it contains that battle's busiest minute. Before it the game is
# still building up; after it the volume falls away and stays down.
#
# The estimate is read off the busier of the two. The other is there to show how
# far the extremes are apart: gm_powf and gm_sqrt agree to within a fraction of
# a per cent across two independent battles, while gm_cosf differs by a quarter
# and gm_floorf by a factor of eight.
#
# Windows are picked by call volume and wall clock, never by time per call. A
# call count is a fact about the game; a nanosecond is a fact about one
# implementation on one machine. Choosing the window by cost would bake that
# implementation into the profile, and comparing implementations is the only
# reason the profile exists.
#
# Regenerate either column with
#
#   sh profile_from_counts.sh <dump>                             lists sessions
#   sh profile_from_counts.sh callcounts-mac-arm64.txt    3 289-1008  battle44
#   sh profile_from_counts.sh callcounts-v2-mac-arm64.txt 3 721-1512  battle69
#
# Applying this profile to a Windows x86 build assumes the game issues the same
# calls there. The simulation is deterministic and the code is the same, but the
# profile itself was not measured on Windows.
#
# gm_lrint / gm_lrintf have no row of their own in the benchmark table; the rint
# row stands in for them.
#
# Columns: gm function, benchmark row, benchmark column (d or f), then the calls
# counted in each window, and the same figures as rates for reading. Only the
# counts are used. They are the counter readings themselves, and the coefficient
# is calls divided by frames worked out where it is needed, so nothing is lost
# to rounding on the way: gm_ceil is 2 936 calls, which shows as 0.0 per frame.
#
# gm_ceilf and gm_floor are zero in both windows. Both are called only in the
# first block of a session, while the map loads, long before either plateau.
#
# Ordered by the busier column.
